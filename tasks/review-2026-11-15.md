# Reliability and performance review — 15 November 2026

This pass reviewed startup/navigation, page lifetime and layout, application shutdown/restart, background persistence, task recurrence, agent-chat persistence, and backup/data migration. It also ran the existing capture, recorder, form and visual checks. This is a focused engineering pass, not a claim that every module and external integration has been exhaustively verified.

## Findings addressed

| Impact | Problem | Result |
|---|---|---|
| High | MainForm constructed all tool pages and later created their hidden native handles. | Only Home is constructed initially. Pages load on first navigation and retain their state. Store events and shutdown tolerate unopened pages. |
| High | Startup and window closes forced full GC, waited for finalizers, and emptied the working set. | Removed the forced collections, trimming imports, timers and redundant visibility override. Windows and the CLR control reclamation. |
| High | Background saves traversed mutable records and nested lists shared with the UI. | Independent recursive snapshots of the supported acyclic record graphs, with cached reflection metadata. Clone failures retain dirty state instead of falling back to live records. |
| High | Asynchronous save failure could be invisible to Exit until a queued UI callback ran. | Failed/pending writes contribute directly to Store.Pending; direct saves retry known failed files. A flush timeout cannot silently proceed as a completed save. |
| High | Agent saves used independently scheduled writes; an old revision could finish last. | One coalescing writer, immutable snapshots, separate queue/file locks, explicit flush/retry, and backup-preserving replacement. Serialization moved off the UI thread. |
| High | A queued save could recreate a deleted agent chat. | Deletion cancels queued/failed writes and blocks the in-flight revision. Tombstones are cleared when the writer drains. |
| High | “Back up all data” omitted nested agent histories and other payloads. | Copies the complete data tree, including nested chats and backups, after flushing both stores. Internal restore staging and temporary writes are excluded. |
| High | Restore deleted live JSON before the replacement copy completed. | Typed JSON validation, staging, folder replacement, previous-folder retention, and a recovery marker for interruption between renames. Image-directory creation follows restore. |
| High | Migration skipped occupied destination files and allowed overlapping trees. | Requires an empty, separate destination; rejects reparse points; checks saves first; updates the location atomically after a successful copy. |
| Medium | Restart lost explicit --data; moving while using --data could return to the old location. | Restarts quote and preserve the override; a completed migration updates the restart override. |
| Medium | Recurrence loop stopped after 5,000 iterations, drifted during skipped months, and could overflow dates. | Direct interval calculations, month/year anchoring, weekend handling and safe completion when no later occurrence exists. |
| Medium | Null chat messages and malformed timestamps could break transcript rendering. | Loaded chat records normalize null entries, text and timestamps; IDs come from their actual filename. |
| Medium | Dashboard forced a minimum content width exceeding a narrow host. | Content fits its available width. |
| Medium | Prompt action label clipped in a narrow editor. | Concise Copy label; Ctrl+Enter remains supported. |
| Low | Default compile-test filename differed from the filename all suites loaded; shortcut checks rejected disabled defaults. | Consistent build target, corrected disabled-shortcut expectation, one complete test runner. |

## Measurements

`tools/measure-ui.ps1` loads types into Windows PowerShell, uses an empty isolated data fixture and constructs/disposes hidden MainForm instances. It never runs Program.Main or opens windows. The first iteration includes JIT/static initialization. Subsequent iterations share the host process. These are component timings, not end-to-end application startup or idle resource measurements.

| Run | First construction | Second | Third |
|---|---:|---:|---:|
| Original, first baseline | 2,635.84 ms | 2,088.60 ms | 2,101.05 ms |
| Updated, final source | 420.84 ms | 82.09 ms | 89.02 ms |

Machine load varied; a second baseline ranged from 2,749 to 3,822 ms. These small samples establish a substantial construction improvement, not a latency guarantee. Raw reports are under `build-test` when the measurements are run. Private/managed memory figures include PowerShell and depend on natural GC timing; they are deliberately not presented as live-app RAM savings. Removing EmptyWorkingSet can increase the displayed working set while avoiding page faults on the next interaction.

Unused pages allocate no controls. Once visited, they remain resident to preserve editing state and make return visits fast. Existing process/drive view visibility gates remain in place. Use `tools/measure-process.ps1` against the updated application to establish real visible/idle CPU and memory for the workload of interest.

The final run's result is reported in the delivery message.

New regression cases cover independent nested snapshots, lazy navigation/state retention, unknown navigation, ancient recurring dates/weekends/month ends/date exhaustion, full nested backup, typed validation, staged restore and retained originals, interrupted-swap recovery, ordered burst saves, deletion during a pending save, and migration destination/override handling. ## Research and choices

- [Microsoft: induced collections](https://learn.microsoft.com/dotnet/standard/garbage-collection/induced) explains why frequent forced collections can reduce performance. This supports deleting the automatic trimming routine.
- [Microsoft: working sets](https://learn.microsoft.com/en-us/windows/win32/memory/working-set) explains page faults when reclaimed pages are referenced again. A smaller displayed working set is not proof of lower allocations.
- [CopyQ's upstream FAQ](https://github.com/hluk/CopyQ/blob/master/docs/faq.rst) describes bounded histories, offloading large items, and unloading inactive tabs. The applicable choice here was deferring unused tool pages; existing image-on-disk storage and history limits were retained.
- [CopyQ security documentation](https://github.com/hluk/CopyQ/blob/master/docs/security.rst) documents ignoring secret clipboard formats. This app already has private-format checks; no duplicate privacy subsystem was added.
- [Ditto upstream](https://github.com/sabrogden/Ditto) and [ShareX clipboard viewer](https://getsharex.com/docs/clipboard-viewer) were considered for workflow ideas. No third-party source or dependencies were copied.

## Remaining verification and tradeoffs

Live desktop interaction, real idle CPU/RAM, Windows Terminal tiling, Office COM, corporate portals, actual screen capture/OCR and external agent CLIs were not exercised against the user's running session. Test fixtures cannot establish their behavior. Large backup/migration copies remain synchronous; long chat histories are still loaded as complete records. Very large datasets warrant a separate measured pass on those workflows. Cloud sync, encryption and new unrelated tools were not added.
